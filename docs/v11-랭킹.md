# 포켓몬 윷놀이 v11 — 🥇 랭킹

> 상태: **구현 완료** (2026-10-02, `APP_VERSION 2026-10-02b`)
> 사용자 확정: 랭킹 + 필터(포켓몬 수 · 전설 수 · 승리 수) · 범위는 **모두 (서버)** — 💾 저장 코드를 켠 프로필끼리, 친구네 포함
> ✅ Firebase 규칙 `yutrank` 게시 완료 (2026-10-02 확인: 목록 읽기·올바른 줄 쓰기 200 · 숫자 빠진 줄·잘못된 번호·긴 이름 401 · 다른 자리 그대로 · 실제 주소 랭킹 화면에 지온이 표시)

## 1. 한눈에

```
처음 화면 🥇 랭킹
  [📕 포켓몬] [👑 전설] [🏆 승리]      ← 필터
  🥇 민준      9마리
  🥈 지온이 우리  3마리
  🥉 서아      1마리
  …
  💾 👤 프로필에서 저장 코드를 켜면 랭킹에 나와요 [👤 프로필로]   ← 등록 안 한 사람 이름은 안 보임 (2026-10-02)
```

## 2. 정한 것

| 곳 | 정한 것 |
| --- | --- |
| 누가 | 💾 저장 코드를 켠 프로필만 (친구네 패드 포함). 저장을 끄거나 프로필을 지우면 빠진다 |
| 숫자 | 📕 포켓몬 = 잡은 포켓몬 수 (보관함) · 👑 전설 = 그중 전설 가족 · 🏆 승리 = 가족 + 로켓단 + 친구 대결 이긴 수 |
| 줄 세우기 | 고른 숫자가 큰 순 (같으면 포켓몬 수 → 승리 수 → 먼저 올린 사람). 같은 숫자는 같은 등수. 1~3등은 🥇🥈🥉 (0이면 메달 없음). 50등까지 |
| 우리 | 이 패드 프로필은 빨간 테두리 + "우리" |
| 올리는 때 | 저장 코드로 저장할 때마다 같이 + 랭킹 화면을 열 때 내 숫자를 먼저 새로 |
| 안전 | 서버 `yutrank` 에는 **이름 · 캐릭터 · 숫자 3개뿐**. 저장 코드 대신 따로 만든 **랭킹 번호(10글자)**를 쓴다 — 랭킹 목록은 누구나 읽어서, 코드가 보이면 남이 기록을 불러갈 수 있으니까. 랭킹 번호는 저장 기록 안에 같이 저장돼서 다른 패드에서 불러와도 한 줄 |

## 3. 서버 자료

`yutrank/{랭킹 번호}` = `{ name, avatar, mons, legends, wins, updated }`

## 4. 시험

- `scenario_save`: 랭킹 서버엔 숫자만(저장 코드 없음) · 지온이 숫자 · 필터 3개 순서 · "우리" 표시 · 저장 안 켠 사람 안내 · 다른 패드에서 불러와 저장해도 한 줄

## 5. Firebase 규칙 (사용자가 할 일)

`"yutsaves"` 덩어리 뒤에 쉼표 `,` 를 붙이고 아래를 같은 높이에 추가 → 게시

```json
"yutrank": {
  ".read": true,
  "$rid": {
    ".write": true,
    ".validate": "$rid.matches(/^[a-z0-9]{10}$/) && newData.child('name').isString() && newData.child('name').val().length <= 12 && newData.child('mons').isNumber() && newData.child('legends').isNumber() && newData.child('wins').isNumber()"
  }
}
```
