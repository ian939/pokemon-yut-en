## 4. 화면 흐름

1. 처음 화면에 **🏠 친구 대결** 버튼
2. **방 만들기**: 우리 팀(지온이…) 고르기 + 판 설정 → 코드 크게 "4 8 2 7" + "친구를 기다려요… 🕐" (그만두기 버튼)

6. 상대가 던지고 두는 모습이 내 패드에서 **그대로 연출**(윷가락·말 이동·배틀·진화·기술 장면). 상대가 풀숲에서 조우 중이면 "하윤이네가 풀숲에서 ○○를 만났어요! 🌿"

## 5. 설계

### 5-1. 서버 자료 `yutrooms/{코드}`

```js
{
  v: 1, created, updated,
  host: { name: "🧒 지온이", dev }, guest: { name: "하윤이네", dev } | null,
  status: "wait" | "pick" | "play" | "over",
  settings: { pieces, backdo, skills, battle },
  picks: { 0: [ids], 1: [ids] },         // 고르기
  seq: 17,                                // 몇 번째 동작
  state: {...},                           // 판 상태 전체 (지금 저장 형식 그대로)
  last: { seq, by: 0 | 1, events: [...], note }   // 마지막 동작의 연출거리
}
```

### 5-2. 동기화 — "자기 차례인 패드가 계산해서 올린다"

- 규칙 엔진은 그대로. **차례인 패드**가 던지기·두기·기술을 계산하고 `{ state, last, seq+1 }`을 올린다
- 올릴 때 Firebase **ETag 조건부 쓰기**로 겹쳐 쓰기를 막는다 (두 패드가 동시에 누르는 일 방지)
- 다른 패드는 **실시간 구독**(Firebase REST 스트리밍, 안 되면 1.5초마다 확인)으로 받아서 `last.events`를 지금과 같은 연출로 보여 주고 상태를 바꾼다
- 풀숲 조우·시계 문제·볼 던지기·말 바꾸기·기술 넘겨주기 고르기는 **그 팀 패드에서만** — 결과(뽑힌 포켓몬·말 바꾸기)만 판 상태로 올라가고, 다른 패드엔 한 줄 알림
- 보상(상자·가방·보관함·공부 기록)은 각 패드의 저장에만 — 서버에는 안 올린다

### 5-3. 엔진·화면 바꿀 곳

- 엔진: 거의 없음 (판 상태가 이미 JSON이라 그대로 올리고 받는다)
- 화면: 친구 대결 메뉴 · 방 만들기/들어가기 · 숫자판 · 기다리기 · 고르기 차례 · "내 팀은 몇 번" (`G.me`) — 사람 차례 판정(`humanTurn`)을 "내 팀 차례"로 · 상대 동작 받아 연출 · 이어하기
- 로컬 저장: 진행 중인 친구 대결은 `{ code, me }`만 기억 (판은 서버에서)

## 6. 테스트

- 화면 검사에 **가짜 Firebase 서버**(파이썬, 읽기·쓰기·ETag·스트리밍)를 띄우고 `?db=` 로 붙인다 → 브라우저 창 두 개로 방 만들기 → 코드로 들어가기 → 고르기 → 번갈아 두기 → 배틀·풀숲 → 끝(각자 상자)까지
- 끊김: 한쪽 창을 새로고침·닫았다 열기 → 이어하기 / 동시에 누르기 → 한쪽만 들어감
- 실제 서버: 규칙을 넣은 뒤 두 기기(PC 브라우저 + 패드)로 한 판

## 7. Firebase 규칙 (사용자가 할 일)

Firebase 콘솔 → elglishmon → Realtime Database → **규칙** 탭에서, 지금 있는 `"families"` 줄 옆에 아래를 **추가**하고 게시:

```json
"yutrooms": {
  "$code": {
    ".read": true,
    ".write": true,
    ".validate": "$code.matches(/^[0-9]{4}$/)"
  }
}
```

(전체 모양 예: `{ "rules": { "families": { ...지금 그대로... }, "yutrooms": { ...위... } } }`) — 코드 4자리 방만 읽고 쓸 수 있다. 잉글리시몬 `families` 자료는 건드리지 않는다

## 9. 구현하며 정한 것

| 곳 | 정한 것 |
| --- | --- |
| 올리는 모양 | 판 상태·연출은 **JSON 글자**(`stateJ`·`lastJ`)로 — Firebase 는 빈 배열·null 을 지워서 그대로 올리면 판이 망가진다 |
| 겹쳐 쓰기 | ETag 대신 **차례인 패드만 쓴다**. 연출·풀숲 조우·선물 고르기가 끝날 때까지 `busy: true` 로 올려서 상대 패드는 기다린다 (던지기 버튼 꺼짐) |
| 받기 | Firebase 스트리밍(EventSource) + 4초마다 확인. 받은 동작은 줄 세워 차례대로 연출 |
| 보상 | 이긴 집 볼 3개 보물상자 · 진 집 위로 상자(몬스터볼 1개) + 돈 문제 — 각 패드 저장에만. 🏆 전적에 "🏠 친구 대결" |
| 끝 화면 | "한 판 더" 없이 "처음으로" (다시 하려면 새 방) |
| 이어하기 | 코드·팀 번호만 기억(`net`) → 처음 화면 "🏠 친구 대결 이어하기" → 서버에서 최신 판을 받아 이어서. 끝난 판은 빠짐 |
| 시험 | `tools/fake_firebase.py`(가짜 서버: 읽기·쓰기·합치기·스트리밍) + `?db=` · 화면 검사 `--net-only` — 두 창으로 방 만들기 → 틀린 코드 → 들어가기 → 고르기(찜) → 한 판 끝까지(차례 아닌 패드 버튼 꺼짐 · 두 패드 판 같음 · 이긴 팀 같음 · 각자 보상) → 새로고침 이어하기 |
