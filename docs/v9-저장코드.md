## 1. 한눈에

```
처음 화면 💾 저장 → "저장 켜기" → 코드 6자리 (예: 482 719) + "📸 부모님께 사진 찍어 달라고 해요!"
        ▼ 그다음부터 저절로
포켓몬을 잡거나 상자를 열거나 판이 끝나면 몇 초 뒤 서버에 저장
        ▼ 새 패드 · 기록이 지워졌을 때
처음 화면 💾 저장 → "코드로 불러오기" → 숫자판 6자리 → "불러오기" 라고 써서 확인 → 그대로!
```

## 2. 정한 것

| 곳 | 정한 것 |
| --- | --- |
| 방법 | ✅ 저장 코드 **숫자 6자리** (친구 대결 방 코드 4자리와 헷갈리지 않게) |
| 저장하는 것 | 📕 잡은 포켓몬 · 🎒 가방의 볼 · 🏆 전적 · 📖 본 기술 · 🎓 공부 기록 · ⚙️ 판 설정 · 지난번 고른 포켓몬. **하고 있던 판은 안 올린다** (패드에서 이어하기는 그대로) |
| 언제 | 기록이 바뀌면 4초 뒤 저절로 (여러 번 바뀌면 한 번에). 창을 닫거나 다른 앱으로 가면 바로. 인터넷이 끊기면 30초마다 · 연결되면 다시 |
| 불러오기 | 저장된 기록 미리 보기(포켓몬 N마리 · 볼 N개 · N판) + "지금 이 패드의 기록은 **사라지고** 바뀌어요" → **"불러오기"를 직접 써야** 실행 (되돌릴 수 없어서) |
| 패드 두 대 | 📕 잡은 포켓몬은 **합친다** (같은 포켓몬은 먼저 잡은 때로). 볼 · 전적 · 공부 기록 · 설정은 **나중에 저장된 쪽** (볼을 합치면 늘어나서). 처음 화면에 올 때 다른 패드가 더 나중에 저장했으면 받아 온다 |
| 코드 보기 | 💾 저장을 누르면 언제든 코드 · 마지막 저장 시각 · 지금 기록 수 · "지금 저장" · "다른 코드 불러오기" · "저장 끄기" |
| 끄기 | 이 패드에서 저장만 멈춘다 (서버 기록은 남아서 코드로 다시 불러올 수 있음) |
| 안전 | 올라가는 건 포켓몬 번호 · 볼 개수 · 전적 숫자 · 버튼 이름(🧒 지온이 등)뿐. 사진 · 글쓰기 없음 |

## 3. 서버 자료

`yutsaves/{6자리}` = `{ v: 1, updated: 시각, dataJ: "기록 JSON 글자" }` — 친구 대결처럼 JSON 글자로 (Firebase 가 빈 배열을 지워서)

## 4. 시험

- `tools/test-ui.py` 의 `scenario_save` — 가짜 Firebase 로 패드 두 대: 켜기(6자리) → 저절로 저장 → 틀린 코드 → 맞는 코드 → 글자 입력 확인 → 바뀜 → 두 패드가 각자 잡은 포켓몬이 합쳐짐 · 볼은 나중 것 → 처음 화면에서 받아 오기 → 끄기

## 5. Firebase 규칙 (사용자가 할 일)

Firebase 콘솔 → elglishmon → Realtime Database → **규칙** 탭에서 `"yutrooms"` 옆에 추가하고 게시:

```json
"yutsaves": {
  "$code": {
    ".read": true,
    ".write": true,
    ".validate": "$code.matches(/^[0-9]{6}$/)"
  }
}
```

규칙을 넣기 전에 저장을 켜면 "⚠️ 서버가 아직 준비 안 됐어요" 안내가 나오고 이 패드 기록은 그대로다.
